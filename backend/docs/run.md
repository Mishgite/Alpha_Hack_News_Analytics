# Настройка и запуск проекта

Python **3.12**, PostgreSQL **17.x**, Node.js **22.12+**. Основной способ запуска: PyCharm

## 1. Окружение и база

1. Открыть в PyCharm корень репозитория с папками `backend`, `frontend` и `.run`
2. Выполнить [настройку PostgreSQL и Python](database-setup.md): установить PostgreSQL, создать базу `alfa_news`, создать Virtualenv в **`backend/app/.venv`**
3. Выбрать это окружение интерпретатором проекта, установить `backend/app/requirements.txt` через **Install requirements**
4. Отметить папку `backend` через **Mark Directory as → Sources Root**
5. Скопировать `backend/app/.env.example` в `backend/app/.env`, заменить пароль в `DATABASE_URL` на локальный пароль PostgreSQL
6. Открыть `backend/app/infrastructure/database/init_db.py` и выбрать **Run 'init_db'**. В конце вывода должны быть `Reaction trigger: OK` и `OK`

База хранится в каталоге PostgreSQL вне репозитория. Окружение, `.env` и локальная БД не передаются через Git

## 2. Компании и новости

1. Получить исходный `df_Uid_data_hack.csv` из материалов организаторов или у команды
2. Создать папку `backend/data/companies` и положить CSV туда
3. Открыть `backend/app/import_companies.py`, выбрать **Run**, в консоли выбрать `1`, затем ввести `100` для частичной загрузки. Вариант `2` загружает все подходящие строки
4. Открыть `backend/app/import_news.py` и выбрать **Run** без параметров. Он загрузит 104 реальные публикации из `backend/data/examples/recent-news-2026-10-25.json` с готовыми признаками, без вызова модели

Повторный импорт не создаёт дубли. Начальные темы компании заполняются по ОКВЭД при входе; ждать LLM-разметки для первой подборки не требуется. В выборе компании отображаются только записи из локальной БД

CSV не хранится в Git. JSON с примерами новостей скачивается вместе с кодом. Даты публикаций сохранены: после выхода новостей за выбранный период лента может быть пустой. Для текущих новостей нужен воркер; для старых примеров: **Фильтр → За месяц → Применить**

Если CSV ещё нет: запустить `backend/app/demo_data.py` и выбрать компанию `demo-api-company`. Это отдельная синтетическая компания с тремя тестовыми новостями для проверки подключения и интерфейса

Подробнее: [импорт компаний](import-companies.md), [новости и параметры импорта](news-examples.md)

## 3. Материалы для AI-разбора

1. Получить у команды подготовленный каталог `reports_processed`: подпапки с `manifest.json` и JSON страниц
2. Поместить его в `backend/data/reports_processed`. Исходные PDF хранить отдельно в `backend/data/reports`
3. Открыть `backend/app/import_reports.py` и выбрать **Run**. Проверить, что в результате нет ошибок импорта

Эти материалы не передаются через Git. Скрипт читает подготовленные тексты, а не распознаёт PDF. Без них приложение запускается, но разбор не сможет сослаться на отсутствующие отчёты банка

## 4. Модель и лимиты

В `backend/app/.env`:

1. Заменить `LLM_API_KEY` на ключ команды, выданный организаторами
2. Проверить `LLM_BASE_URL` и три параметра `LLM_MODEL_*` по `backend/app/.env.example`; использовать модели API хакатона
3. Оставить `API_DEMO_ENABLED=true` для выбора компании и входа
4. Для локального фронта оставить адреса `http://127.0.0.1:5173` и `http://localhost:5173` в JSON-массиве `API_CORS_ORIGINS`
5. Согласовать с командой лимиты перед запуском воркера

Параметры расходов:

- `LLM_DAILY_REQUEST_LIMIT=100`: максимум попыток за сутки UTC в одной БД, включая ошибки. Если на этой БД уже выполнялись проверки, их попытки тоже входят в лимит
- `LLM_BUDGET_RESERVE_RUB=50`: остановка новых платных вызовов при остатке 50 ₽ или меньше на общем ключе
- `LLM_MAX_OUTPUT_TOKENS=8192`: предел длины ответа модели

Резерв 50 ₽ означает сохранение остатка, а не расход не больше 50 ₽. Для проверок в пределах 150 ₽ из полностью доступных 500 ₽ резерв должен быть не меньше 350 ₽. Проверка остатка не резервирует деньги: параллельные запросы и стоимость последнего вызова могут привести к превышению такого ориентира

Воркер расходует бюджет и без нажатия кнопки разбора: размечает новые новости и профили. На разных компьютерах локальные счётчики независимы, а ключ и денежный бюджет общие. Подробности: [воркер, источники и лимиты](worker.md)

Ключ хранится только на стороне бэкенда. Для запуска ленты без AI-разборов он не нужен

## 5. Фронтенд

1. Если Node.js отсутствует, установить LTS-версию не ниже 22.12 с [официальной страницы](https://nodejs.org/en/download), затем перезапустить PyCharm
2. В настройках PyCharm найти **Node.js** и выбрать установленный интерпретатор
3. Открыть терминал в папке `frontend`, проверить `node --version`, затем выполнить `npm ci`. Если PowerShell блокирует `npm.ps1`, использовать `npm.cmd ci` и `npm.cmd run dev`
4. Скопировать `frontend/.env.example` в `frontend/.env.local`
5. Для локального API оставить:

   ```dotenv
   VITE_API_URL=http://127.0.0.1:8000
   ```

Адрес указывается без `/api` в конце. После изменения `.env.local` фронт нужно перезапустить

## 6. Запуск в PyCharm

В верхнем списке конфигураций выбрать:

- **Без воркера**: фронт и API, сохранённые новости, профиль, реакции и готовые разборы
- **Все сервисы**: фронт, API и воркер, включая сбор новостей, разметку, котировки и новые разборы

Нажать **Run**, затем открыть **http://127.0.0.1:5173**. На экране входа выбрать компанию и роль, открыть подборку

Отдельные конфигурации: **Backend**, **Frontend**, **Worker**, **БД - создать таблицы**, **БД - проверить**. Они находятся в `.run` и используют интерпретатор проекта. Если не появились, переоткрыть проект. При ошибке интерпретатора выбрать окружение из шага 1 в настройках соответствующей конфигурации

Если npm-конфигурации недоступны в редакции PyCharm:

1. Запустить `backend/app/server.py` через **Run**
2. В терминале из `frontend` выполнить `npm run dev`
3. Для фоновой обработки отдельно запустить `backend/app/worker.py` через **Run**

Нужна одна копия API, фронта и воркера. Перед переключением общих конфигураций остановить прежние процессы через **Stop**. PostgreSQL работает как системная служба; общие конфигурации его не запускают

Без воркера новые разборы не выполняются. Уточняющие вопросы по готовому разбору обращаются к модели через API и расходуют бюджет даже без воркера

## 7. Проверка запуска

1. Открыть **http://127.0.0.1:8000/health**: ответ должен содержать `status: "ok"`. Это проверка HTTP-сервера; подключение к БД проверяет конфигурация **БД - проверить**
2. Открыть **http://127.0.0.1:8000/docs**: должна загрузиться документация API
3. На фронте войти с компанией, открыть подборку и новость. Проверить изменение личных тем через **Темы подборки**
4. Для проверки AI запустить воркер и нажать **Разобрать влияние** на одной новости. Дождаться результата; это платная проверка

Для проверки состояния воркера в Swagger выполнить `POST /api/auth/demo` с существующим `company_id` и `job_role: "ceo"`, скопировать `access_token` из ответа в **Authorize**, затем вызвать `GET /api/status`. При готовом воркере ожидаются `worker_alive=true` и `analysis_available=true`; платный вызов также зависит от доступности шлюза и остатка бюджета

## После git pull

1. Если изменился `backend/app/requirements.txt`, выполнить **Install requirements**
2. Если изменился `frontend/package-lock.json`, выполнить `npm ci` в `frontend`
3. Добавить новые параметры из `.env.example` в свои `.env`, сохранив локальные пароли и ключи
4. Для обновления справочника тем повторно запустить `init_db.py`. Скрипт не заменяет обновление структуры существующих таблиц: при изменении схемы нужны инструкции к конкретному обновлению
5. Если обновилась разметка примеров, у конфигурации `import_news` в **Run → Edit Configurations → Parameters** указать `--refresh-features`, выполнить один раз, затем убрать параметр
6. Перезапустить API, фронт и воркер

## Если запуск не удался

- **Пустой список компаний**: выполнить импорт компаний или `demo_data.py`; проверить, что API и импорт используют одну БД
- **Пустая лента**: проверить импорт новостей и темы компании, сбросить фильтр по дате, если он включён. Не каждая новость подходит каждой компании
- **Invalid Python interpreter / No module named ...**: выбрать `backend/app/.venv` и установить зависимости именно туда
- **Unresolved reference 'app'**: отметить `backend` как **Sources Root**
- **Ошибка PostgreSQL**: проверить службу, базу `alfa_news` и `DATABASE_URL`; [настройка БД](database-setup.md)
- **Port is already in use / WinError 10048**: остановить прежний процесс на 5173 или 8000
- **Фронт не получает данные**: проверить `/health`, `VITE_API_URL` и `API_CORS_ORIGINS`. При общем запуске API может стартовать позже фронта; после его старта повторить загрузку
- **Разбор недоступен**: проверить процесс Worker, параметры LLM, лимиты и его консоль

## Публикация

Для GitHub Pages фронтенд собирается отдельно, API и PostgreSQL размещаются на сервере. Нужен публичный HTTPS-адрес API и разрешённый origin фронта в CORS. Порядок: [GitHub Pages](../../frontend/README.md#github-pages)

## Перед демонстрацией

1. Запустить **Все сервисы**. Проверить доступность API, воркера и остаток бюджета по шагу 7
2. Через **Настроить демо** выбрать `U_211` (медицина), затем `U_206` (IT) или `U_225` (перевозки), сохраняя одинаковые роль и период. Сравнить первые новости
3. Открыть **Почему в подборке**, затем **Темы подборки**. Через **Добавить темы** найти личный интерес, отметить и сохранить. Уже выбранные темы показаны отдельно
4. Для `U_225` открыть разбор новости о прогнозе экспорта муки и логистике в Причерноморье. Открыть цитату и **Данные для вывода**, задать уточняющий вопрос
5. Открыть **Биржевой обзор**, найти инструмент и посмотреть его данные. Вне торгов актуальных сделок может не быть; время котировок указано в карточке инструмента

Готовые разборы и история вопросов хранятся в локальной БД и через Git не передаются. На другом компьютере первый разбор нужно выполнить заранее с работающим воркером. Если подтверждённой позиции банка по событию нет, показывается это ограничение
