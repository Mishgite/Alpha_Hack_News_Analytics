# API

Адрес: `http://127.0.0.1:8000`. Swagger с параметрами и схемами ответов: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

## Запуск в PyCharm

1. Настроить окружение и БД по [инструкции](database-setup.md)
2. Установить обновлённый `app/requirements.txt` в интерпретатор проекта
3. Для проверки без парсера и LLM открыть `app/demo_data.py` и выбрать **Run 'demo_data'**
4. Открыть `app/server.py` и выбрать **Run 'server'**
5. Открыть Swagger

`demo_data.py` добавляет компанию `demo-api-company`, отдельную тему и три новости с пометкой «ДЕМО». Повторный запуск обновляет эти же записи и даты, без дублей. Это синтетические примеры, без ссылок на реальные публикации. Обычный запуск сервера данные не создаёт и LLM не вызывает.

## Проверка ленты

1. В Swagger выполнить `POST /api/auth/demo` с телом:

   ```json
   {"company_id": "demo-api-company", "job_role": "cfo"}
   ```

2. Скопировать `access_token` из ответа
3. Нажать **Authorize**, вставить токен без слова `Bearer`, подтвердить
4. Выполнить `POST /api/feed` с телом `{"days": 7, "page_size": 2}`
5. Для следующей страницы вызвать `GET /api/feed/{snapshot_id}`: взять `snapshot_id` и `next_position` из ответа, передать `next_position` как `position`

Фронтенд передаёт токен в заголовке `Authorization: Bearer <access_token>`. `user_id` в запросах не нужен: API получает его из сессии. Токен выдаётся на 24 часа.

## Методы

Везде, кроме `/health`, `/api/companies` и `/api/auth/demo`, нужен токен.

**Вход и профиль**

- `GET /api/companies` — список компаний для демовхода; query: `limit` (1–100), `offset` (от 0), `query` (поиск по ID, отрасли, ОКВЭД, городу или региону), `demo_selection=true` (только 50 компаний из `app/demo_companies.json`; поиск применяется внутри этого набора)
- `POST /api/auth/demo` — создать демопользователя; body: `company_id`, `job_role`; `city` необязателен и не участвует в географии рекомендаций; ответ: `user`, `access_token`, `token_type`, `expires_at`
- `POST /api/auth/logout` — отозвать текущую сессию; ответ: 204 без тела
- `GET /api/profile` — пользователь, компания, темы и реакции
- `PUT /api/profile/company` — сменить компанию; body: `company_id`
- `PUT /api/profile/settings` — заменить настройки; body: `job_role`; `city` необязателен, без него сохранённый город не меняется
- `PUT /api/profile/interests` — заменить интересы; body: `personal` и `disabled`, оба значения являются списками ID тем
- `GET /api/tags` — справочник активных тем: `id`, `display_name`
- `GET /api/profile/context` — снимок фактических признаков компании и их происхождение
- `GET /api/profile/priorities` — эффективные веса тем с учётом должности, интересов и реакций

Роли: `ceo`, `cfo`, `accountant`, `treasury`, `employee`, `other`.

**Лента и реакции**

- `POST /api/feed` — создать ленту; body: `days` (1–365, по умолчанию 7), `page_size` (1–100, по умолчанию 20); можно передать `{}`
- `GET /api/feed/{snapshot_id}` — прочитать страницу; query: `position` (от 0), `limit` (1–100)
- `GET /api/news/{news_id}` — полный текст новости, дата, источник и признаки
- `PUT /api/news/{news_id}/reaction` — поставить или снять реакцию; body: `snapshot_id`, `reaction` (`like`, `dislike`, `none`)
- `POST /api/impressions` — сохранить показ; body: `event_id`, `snapshot_id`, `news_id`, `occurred_at` (ISO 8601 с часовым поясом); один показ на пользователя, новость и снимок, включая повтор с другим `event_id`
- `POST /api/news/{news_id}/open` — сохранить открытие текста из ленты; body: `event_id`, `snapshot_id`, `occurred_at`; одно открытие на пользователя, новость и снимок. Обычный `GET /api/news/{news_id}` событие не создаёт
- `POST /api/news/{news_id}/tag-feedback` — сообщить об ошибке разметки; body: `snapshot_id`, `wrong_tag_ids`, `suggested_tag_ids` (оба списка необязательные, но хотя бы один должен быть непустым)

Ответ ленты: `snapshot_id`, `generated_at`, `expires_at`, `items`, `has_more`, `next_position`. Каждый элемент содержит `title`, `summary`, `published_at`, `source_url`, `tags`, `my_reaction` и `ranking`; ID новости находится в `ranking.news_id`.

Снимок действует 30 минут. После смены компании нужен новый снимок. Реакции влияют на следующее создание ленты, порядок существующего снимка сохраняется.

Показ отправляется при видимости не менее 50% карточки в активной вкладке. Открытие отправляется после загрузки и отображения текста по действию пользователя. Повторы запроса используют прежний `event_id`; ID другого события вызывает 400. Данные браузера, время чтения и тексты в этих событиях не собираются.

**AI и состояние**

- `POST /api/news/{news_id}/analysis` — создать задание; body: `{"idempotency_key": "уникальный-ключ-действия"}`; ответ: 202 и задание с `id`, `status`, `analysis_id`, `error_code`
- `GET /api/analysis-jobs/{job_id}` — состояние задания: `queued`, `running`, `ready`, `failed`
- `GET /api/analyses/{analysis_id}` — сохранённый разбор с источниками
- `GET /api/analyses/{analysis_id}/trace` — выполненные шаги: план поиска, найденные фрагменты, проверки и использование кеша
- `GET /api/analyses/{analysis_id}/context` — снимок компании на момент разбора: `ContextData` с `payload_json` и версиями источников; проверяет доступ к компании разбора
- `POST /api/analyses/{analysis_id}/questions` — уточняющий вопрос; body: `conversation_id` (UUID), `question` (1–1000 символов); ответ: сохранённый вопрос, `answer`, `sources_json`
- `GET /api/analyses/{analysis_id}/conversations/{conversation_id}` — сохранённая история текущего пользователя; query: `limit` (1–50)
- `GET /api/report-chunks/{chunk_id}` — текст цитируемого фрагмента, страница и метаданные PDF
- `GET /api/report-chunks/{chunk_id}/document` — исходный PDF, если он есть в `backend/data/reports`; изменившаяся версия файла возвращает 409
- `GET /api/status` — доступность воркера, последнее состояние биржи и последний проверенный бюджет шлюза
- `GET /health` — состояние HTTP-сервера и подключённых функций; доступность БД не проверяет

Порядок разбора: создать задание, опрашивать его раз в 2–3 секунды до `ready` или `failed`, затем прочитать `analysis_id`. При повторе потерявшегося HTTP-запроса передавать прежний `idempotency_key`. Для новой попытки после `failed` использовать новый ключ. Максимум три незавершённых задания на пользователя.

Без запущенного [воркера](worker.md) или настроенной модели создание задания возвращает 503. `ready` у задания означает, что результат сохранён; сам разбор может иметь `status="partial"` и перечислять недостающие подтверждения. Непроверенный ответ модели не публикуется. Повтор того же разбора использует кеш с учётом версии новости, компании, корпуса и модели.

Для PDF тоже нужен Bearer-токен: фронтенд загружает файл авторизованным запросом, затем открывает полученный Blob. Уточнения используют источники сохранённого разбора и последние пять сообщений; нового поиска событий в интернете они не выполняют.

**Биржа**

- `GET /api/market?limit=20` — последний сохранённый срез MOEX, тепловая карта и до `limit` лидеров изменения (1–100)
- `status`: `ready`, `stale` или `empty`; загрузка с биржи выполняется воркером
- `size_metric`: денежный оборот, а при его отсутствии равный размер; `color_metric`: изменение к предыдущему закрытию в процентах
- `as_of`: время данных источника, `captured_at`: время загрузки; неизвестная задержка передаётся как `null`
- Если источник недоступен или данным больше 30 минут, возвращается сохранённый срез с `stale`

## Ранжирование и данные

`services/ranking.py`, версия `formula-v3-business-context`. Формула учитывает темы компании, личные интересы, должность, деловую значимость и географию. Свежесть не добавляет новости без тематической связи. Локальному событию требуется отраслевая или личная тема; события из другой географии получают меньший балл.

`ranking.geography_factor` показывает применённое понижение (по умолчанию 1), `geography_bonus` хранит бонус. Старые снимки читаются с прежней версией и сохранёнными оценками. Полная [формула и значения коэффициентов](backend-overview.md#3-формула-рекомендаций).

В `ranking` добавлены `geography_score` (может быть `null`), `geography_bonus`, `geography_reason`, `ranking_version`. Они сохраняются в снимке. У старых снимков географический балл и версия в элементе могут отсутствовать: API возвращает `null`, бонус `0`, старый итоговый балл не пересчитывается. Подробная формула: [обзор](backend-overview.md#3-формула-рекомендаций).

Лента берёт до 500 последних размеченных новостей за выбранный период. Без готовых новостей возвращает пустой `items`. Темы с нулевым весом не повышают рейтинг, но не удаляют новости из выдачи.

Для подключения модели заменить `rank_news` в `api/dependencies.py` и обновить `ranking_config_version`. Вход: `RankingRequest`, выход: `RankingResult`. Текущая схема допускает методы `weighted_formula_v1` и `knn_cosine_v1`; для другого алгоритма потребуется согласованное обновление схемы и ограничения БД.

## Ошибки и настройки

- 400 — операция отклонена сервисом: неизвестная тема, истёкший снимок или изменившиеся данные
- 401 — токен отсутствует, отозван или просрочен
- 403 — нет доступа к снимку, разбору или отключённой демофункции
- 404 — запись не найдена
- 409 — конфликт записи в БД
- 422 — неверные поля, UUID или параметры; `detail` содержит список ошибок
- 500 — внутренняя ошибка
- 503 — БД, воркер или провайдер недоступны, исчерпан пул соединений, ответ модели не прошёл проверку либо достигнут лимит LLM
- 504 — истекло время обращения к модели или уточняющего ответа

Ошибки возвращаются в JSON с полем `detail`. Ошибки полей дают список в `detail`; внутренние ошибки не раскрывают SQL, ключи и ответ провайдера. Для разрешённых адресов фронтенда CORS действует и на ошибки.

Ошибки сервисов возвращаются как `{"detail": "описание"}`. SQL и параметры подключения в ответ не попадают.

В `app/.env`: `API_CORS_ORIGINS` задаёт JSON-массив адресов фронтенда. По умолчанию разрешены `localhost` и `127.0.0.1` на портах 5173 и 3000.

`API_DEMO_ENABLED=true` разрешает вход без пароля и выбор любой компании из БД. Это только имитация банковской авторизации. При `false` каталог компаний, создание демосессий и переключение компаний закрыты; настоящая проверка полномочий банка ещё не подключена. Сервер по умолчанию слушает только `127.0.0.1`.

Маршруты с операциями БД объявлены обычными `def`: FastAPI выполняет их в пуле потоков, синхронные сервисы не блокируют цикл событий. [Документация FastAPI](https://fastapi.tiangolo.com/async/).
