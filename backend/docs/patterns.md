# Паттерны в backend

- **Service Layer**: сервисы выполняют сценарии приложения. `ProfileService.register_demo()` проверяет компанию, создаёт пользователя и сессию, сохраняет изменения. API вызывает один метод. [Код](../app/services/profiles.py)
- **Repository**: репозитории содержат запросы к БД. `NewsRepository.get()` находит новость и возвращает её данные. Сервису не нужно составлять SQL. [Код](../app/infrastructure/database/repositories/news.py)
- **Unit of Work**: общая сессия и транзакция для репозиториев. Регистрация сохраняет пользователя и сессию вместе; при ошибке обе записи откатываются. `UnitOfWork` организует работу репозиториев, транзакцию выполняет SQLAlchemy. [Код](../app/infrastructure/database/uow.py)
- **DTO**: модели Pydantic для передачи между слоями. `StoredNews` содержит прочитанные поля новости и доступен после закрытия сессии БД. [Код](../app/schemas/news.py)
- **Dependency Injection**: зависимости передаются через параметры. `uow_factory` позволяет использовать сервис с подключением к отдельной проверочной БД. Репозитории получают готовую сессию. [Код](../app/services/news.py)
- **Strategy**: `FeedService` вызывает переданную функцию `ranker`. Формулу можно заменить локальной моделью при сохранении контракта `RankingRequest → RankingResult`. Алгоритмы ещё предстоит подключить. [Код](../app/services/feed.py)
- **Factory**: `make_session_factory()` задаёт настройки создания сессий через `sessionmaker`. Каждый вызов полученной фабрики создаёт отдельную сессию. Это простой фабричный приём. [Код](../app/infrastructure/database/session.py)

Service Layer, Repository и Unit of Work организуют работу с БД. DTO задают формат обмена данными. Остальные приёмы реализованы параметрами и функциями, без дополнительных слоёв и иерархий классов.
