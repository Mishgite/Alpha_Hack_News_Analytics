# Проверка рекомендаций · 25.10.2026

Версия: `formula-v3-business-context`. [Формула](backend-overview.md#3-формула-рекомендаций).

## Что исправлено

- У 100 загруженных компаний отсутствовали темы. Начальное заполнение по ОКВЭД теперь выполняется при импорте, демовходе и смене компании
- Свежесть больше не добавляет новости без совпадений тем
- Локальный проект не проходит только по общему интересу директора к инвестициям
- Отдельно учитываются деловая значимость, масштаб события и география
- Демонстрационные источники исключены из обычных лент
- Неизвестный необязательный код города не теряет корректную разметку всей новости
- Запущенный API использовал старую версию кода; после перезапуска `/health` возвращает актуальную версию

## Проверка настоящего API

Все 50 компаний демовыбора, одна должность, одинаковый период 7 дней. HTTP-ошибок нет. Получилась 21 различная первая пятёрка, длина ленты от 2 до 14 новостей. Одинаковая выдача для компаний с одинаковыми признаками допустима; ID не используется для искусственного перемешивания.

Примеры первого материала после дополнения корпуса:

- `U_206`, разработка ПО: отражение расходов на ИИ в форме 3-информ
- `U_211`, врачебная практика: стандарт помощи при внебольничной пневмонии
- `U_111`, передача электроэнергии: результаты работы АЭС
- `U_225`, грузоперевозки: экспорт муки и логистические ограничения

Также проверены смена должности, отключение тем и запрет чтения снимка предыдущей компании. Через браузер проверены вход, смена компании и обновление ленты.

## Оценка качества

Исходный корпус: 101 настоящая новость, без трёх демонстрационных записей. Шесть компаний: оптовая торговля, энергетика, строительство, разработка ПО, медицина, грузоперевозки. Роль везде `ceo`. Две непересекающиеся группы по 24 новости, всего 288 пар. Время сравнения фиксировано: 25.10.2026, 13:00 UTC. Новые четыре публикации в эту оценку не включены.

Оценки `0–3` выставила модель хакатона по текстам и данным компаний, без итогов формулы. Это предварительная автоматическая оценка, а не экспертная разметка. Оценщик и разметчик используют одну модель, поэтому их ошибки могут совпадать. Метки не добавляются в данные пользовательских реакций для обучения.

На первой группе, которую использовали при разработке:

- NDCG@5: `0.472 → 0.774`
- Precision@5: `0.267 → 0.500`
- полностью нерелевантные материалы в первых пяти: `14 → 1`

На второй группе, оценки которой прочитаны после фиксации формулы:

- NDCG@5: `0.322 → 0.275`
- Precision@5: `0.067 → 0.100`
- полностью нерелевантные материалы: `17 → 0`
- три компании получили пустую выдачу внутри этого ограниченного набора

В Precision@5 знаменатель всегда 5, недостающие позиции считаются нулевыми. NDCG использует gain `2^grade−1`; слабосвязанные материалы с оценкой 1 тоже дают вклад. Строгий отбор снизил мусор, но потерял часть слабых связей и полноту. Улучшение качества на произвольных новостях этой проверкой не доказано.

## Техническая проверка

107 проверок бэкенда и 5 subtests прошли, включая PostgreSQL, API, worker с тестовым транспортом, обратную совместимость снимков, ограничения доступа и сбор реакций. 27 проверок фронтенда и сборка прошли. Платные вызовы настоящего разметчика проверены на новости ЦБ и школьном IT-мероприятии; найденная ошибка кода города закреплена отдельным тестом.

Расход шлюза после дополнительного прохода: около 14.08 ₽ за сутки, включая предыдущие вызовы. Последний проход добавил около 0.96 ₽. Лимит проверок 150 ₽ не достигнут. Локальный лимит количества вызовов увеличен до 100, поскольку проверки исчерпали прежние 30; денежный лимит шлюза остаётся отдельным ограничением.

### Дополнительный проход 25 октября

- Подключена неработавшая кнопка признаков компании в AI-разборе
- Ручные корпоративные темы больше не отбрасываются фильтром локальных событий; отключение темы по-прежнему обнуляет её вес
- Одновременные изменения профиля на фронте запрещены, старые ответы загрузки не заменяют новый экран
- Запоздавшие 401 и ответы выхода из прежней сессии не удаляют новую сессию
- Исправлен сдвиг даты новости на предыдущий день при подготовке данных для AI
- Уточняющий вопрос получает значения из снимка компании исходного разбора
- Схема ответа требует признаки для вывода о компании и условия для сценариев; коррекция получает предыдущий ответ и замечания
- При повторном чтении изменённого профиля фронтенд сбрасывает сохранённую ленту
- Конец списка больше не обозначает, что пользователь прочитал все загруженные новости

Настоящая модель сначала дважды отклонила разбор новости о налогах. Диагностика выявила ошибочную дату и неподтверждённые предположения об имуществе компании. После исправлений разбор сохранён с явным отсутствием подтверждённой налоговой обязанности. Для `U_211` через браузер выполнен разбор новости о стандарте помощи: очередь, обработчик, сохранение, ссылки на признаки, уточнение и повторное открытие с историей. Повторное открытие не создало нового задания. Проверка модели не заменяет экспертную проверку правовых или медицинских выводов.

## Что остаётся

Нужны более равномерные отраслевые источники и оценка реальными пользователями. Два общих материала для части компаний означают недостаток подходящих новостей, а не поломку переключения. Расширять ленту нерелевантными публикациями ради количества не следует. Сравнивать следующую версию нужно на новых компаниях и датах, без подбора коэффициентов по тем же оценкам.

Исходные снимки, оценки и результаты проверки находятся локально в `backend/data/ranking-audit/` и исключены из Git. Пересказы и готовые признаки 104 демонстрационных публикаций сохранены в [JSON](../data/examples/recent-news-2026-10-25.json).
