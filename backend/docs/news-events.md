# Публикации одного события

## Хранение и выдача

[Схема обработки новостей](architecture.md#обработка-новостей) показывает место группировки публикаций в общем процессе

`news` хранит отдельные публикации с исходными текстами, URL и датами. Повторная загрузка той же ссылки или внешнего ID обновляет только её запись. `news_events` хранит группы; `news.story_cluster_id` связывает публикацию с событием

После ранжирования новая лента оставляет первую публикацию каждой группы, то есть наиболее подходящую выбранному профилю. В окне новости доступны остальные публикации и ссылки. Уже выданные снимки ленты не переписываются: после группировки нужно обновить подборку

## Как определяется совпадение

Алгоритм `local-events-v1` работает локально, без LLM, загрузки моделей и новых зависимостей

1. Кандидаты одного языка за 48 часов, максимум 300 ближайших по времени публикаций
2. Дословные совпадения определяются по SHA-256 заголовка и текста, если текст не короче 200 символов
3. Для близких пересказов сравниваются значимые слова заголовка и первых 4000 символов текста. Убираются служебные слова, регистр и различие е/ё; русские словоформы сближаются по началу слова
4. Для пересказов нужны одинаковые распознанные названия в заголовке, числа с единицами, отрицания и направление действия. Учитываются географические названия после предлогов в заголовке и начале текста
5. Коэффициент Дайса для заголовка и текста должен быть не ниже 0,85/0,55 либо 0,65/0,80 соответственно
6. Новая публикация должна совпасть с каждым участником группы. Связь A–B и B–C сама по себе не объединяет A и C. В группе максимум 12 публикаций

Это консервативная лексическая группировка. Сильные переформулировки, неизвестные сокращения и неоднозначные случаи могут остаться отдельными карточками. Совпадение темы само по себе не объединяет материалы

## Стоимость и AI-разбор

- Группировка не вызывает платную модель
- Готовая разметка дословного текста того же языка и близкой даты переносится на копию с её ID. Отличающиеся тексты проходят обычную разметку
- Разбор получает максимум три разных текста события. Общий лимит новостного текста остаётся 18000 символов, число шагов модели не увеличивается
- Источники передаются раздельно; цитата проверяется по тому тексту, на который ссылается вывод
- Состав и версии публикаций входят в ключ кеша. Изменение источников во время разбора не позволяет сохранить результат как актуальный. Старые разборы сохраняются для истории

## Обновление и исправление объединений

Новые публикации группируются при сохранении. Для существующей локальной БД запустить `backend/app/group_news.py` через Run: добавится таблица событий, затем обработаются до 5000 публикаций за последние 30 дней. Параметры командного запуска: `python -m app.group_news --days 30 --limit 5000` из `backend`

В Docker-демонстрации новые записи группируются при первоначальном импорте. Повторный запуск готового набора существующие записи не меняет; пересчёт групп старой БД выполняется отдельной командой выше

Для отмены ошибочного объединения: `NewsService().separate_event(news_id)`, импорт `from app.services.news import NewsService`. Метод выделяет публикацию в самостоятельное событие и запрещает её автоматическое повторное объединение. Тексты, реакции и разборы не удаляются

Проверки: `RUN_DATABASE_TESTS=1`, затем `python -m pytest app/test_news_events.py -q` из `backend`. Используется отдельная схема PostgreSQL; запросов к платной модели нет
