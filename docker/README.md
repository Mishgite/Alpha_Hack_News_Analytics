# Запуск в Docker

Нужны Git и запущенный Docker с Compose. Python, Node.js, PostgreSQL и исходные датасеты на компьютере не требуются

## Первый запуск

Из корня клонированного репозитория:

```bash
docker compose -f docker/compose.yaml up --build -d
docker compose -f docker/compose.yaml logs bootstrap
docker compose -f docker/compose.yaml ps -a
```

Открыть **http://127.0.0.1:5173**. API: **http://127.0.0.1:8000/docs**

Порядок запуска: PostgreSQL → схема и начальные данные → API и воркер → фронтенд. `bootstrap` должен завершиться с кодом `0` и сообщением `Demo ready: 50 companies, 104 news, 9 reports`. Остальные сервисы должны стать `healthy`

## Какие данные загружаются

- **50 компаний** из текущей демонстрационной выборки: те же обезличенные ID, отрасли, города, регионы и готовые темы
- **104 реальные новости**: ссылки, исходные даты, краткие пересказы и готовая разметка
- **27 фрагментов девяти отчётов банка**: текст, название документа и страница для поиска и цитирования

Файлы: [`backend/data/examples`](../backend/data/examples). Полных CSV и PDF, точной выручки, банковских продуктов, платежей, связей физлиц, токенов и пользовательских сессий в наборе нет. Поэтому контекст компаний содержит меньше сведений, чем локальная БД команды. Открытие полного PDF требует отдельно добавить оригиналы; цитаты из включённых фрагментов доступны сразу

Загрузка не обращается к LLM. Все записи и отметка об успешном импорте сохраняются одной транзакцией. Ошибка откатывает импорт; после исправления запуск можно повторить. Существующие компании и публикации не заменяются. Повторный запуск завершённого импорта не меняет данные и не создаёт дубли

Даты новостей не сдвигаются. Для просмотра примеров после их устаревания используется фильтр периода над лентой. Новые публикации собирает воркер

## Подключение модели

Для новых AI-разборов, вопросов и разметки свежих публикаций нужен ключ шлюза хакатона:

1. Скопировать `docker/.env.example` в `docker/.env`
2. Заполнить `LLM_API_KEY`
3. Выполнить из корня:

```bash
docker compose --env-file docker/.env -f docker/compose.yaml up -d
```

Без ключа работают выбор компании, лента готовых новостей, настройки тем и реакции. Воркер собирает RSS и обновляет котировки; неразмеченные новые новости не попадают в персональную ленту. AI-разбор без ключа не подменяется фиктивным ответом

`LLM_DAILY_REQUEST_LIMIT=100` ограничивает попытки за сутки UTC; `LLM_BUDGET_RESERVE_RUB=360` останавливает новые обращения при таком остатке средств. Готовые начальные профили и новости повторной разметки не требуют

## Обновление и диагностика

```bash
git pull
docker compose -f docker/compose.yaml up --build -d
docker compose -f docker/compose.yaml logs --tail 100 bootstrap api worker
```

Если используется `.env`, добавлять `--env-file docker/.env` во все команды Compose. Данные сохраняются в Docker volume `alfa-news_postgres-data`. `down` сохраняет volume; `down -v` удаляет БД и нужен только для намеренного полного сброса

Без воркера: `docker compose -f docker/compose.yaml up --build -d frontend`; уже запущенный воркер остановить командой `docker compose -f docker/compose.yaml stop worker`

Источники и интервалы: [`worker.json`](worker.json). После изменения пересобрать образ через `up --build -d`. Для запуска тестового контура рядом с локальным приложением задать `API_PORT`, `FRONTEND_PORT`, соответствующие `VITE_API_URL` и `FRONTEND_ORIGIN`

## Сервер и отдельный фронтенд

1. Скопировать `.env.example` в `.env`, задать собственный `POSTGRES_PASSWORD` и ключ модели
2. Задать `FRONTEND_ORIGIN=https://team.github.io` без пути репозитория
3. Настроить DNS домена API на сервер, указать `API_DOMAIN=api.example.ru`
4. Открыть входящие порты 80 и 443 и выполнить:

```bash
docker compose --env-file docker/.env -f docker/compose.yaml --profile https up --build -d api worker proxy
```

5. В настройках GitHub Pages задать `VITE_API_URL=https://api.example.ru` и собрать фронтенд по [инструкции](../backend/docs/run.md#github-pages)

Контейнер `frontend` на сервере при таком размещении не нужен. База не публикует порт наружу; API по умолчанию слушает только loopback хоста, публичный HTTPS предоставляет Caddy. Стандартный пароль предназначен только для локального запуска. Смена пароля в `.env` не меняет пароль уже созданной роли PostgreSQL
