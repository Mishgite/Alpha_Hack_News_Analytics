# Фронтенд

Vite + JavaScript-модули + CSS. Сборка статическая, маршруты через `#`, подходит для GitHub Pages. Python API и PostgreSQL запускаются отдельно.

## Локальный запуск

Готовые конфигурации PyCharm, включая совместный запуск с API: [инструкция](../backend/docs/run.md).

Node.js 22.12+.

1. Открыть терминал в `frontend`
2. Установить зависимости: `npm ci`
3. Скопировать `.env.example` в `.env.local`
4. Оставить `VITE_API_URL=http://127.0.0.1:8000` для локального API
5. Настроить бэк по [инструкции](../backend/docs/database-setup.md) и запустить `backend/app/server.py` в PyCharm
6. Запустить `npm run dev`
7. Открыть `http://127.0.0.1:5173`

На первом экране доступны поиск компании, город и роль демосценария. Роль находится в отдельном блоке вне интерфейса банковского приложения. Вход создаёт демопользователя на сервере, сессия хранится в текущей вкладке.

Для проверки на синтетических данных БД один раз запустить `backend/app/demo_data.py`. После этого найти `demo-api-company`. Скрипт создаёт три новости с пометкой «ДЕМО», модель не вызывает.

Для AI-разборов нужен настроенный [воркер](../backend/docs/worker.md). Без него лента и профиль работают, разбор показывает ошибку доступности. Ключ LLM на фронтенд не передаётся.

## GitHub Pages

1. Разместить FastAPI на сервере с публичным HTTPS-адресом
2. На сервере в `backend/app/.env` добавить адрес фронтенда в `API_CORS_ORIGINS`, например:

   ```dotenv
   API_CORS_ORIGINS=["https://mishgite.github.io"]
   ```

   Здесь указывается origin без пути репозитория. Перезапустить API. `API_DEMO_ENABLED=true` разрешает демонстрационный вход; настоящая банковская авторизация ещё не реализована.

3. В репозитории открыть **Settings → Secrets and variables → Actions → Variables** и создать `VITE_API_URL`, например `https://api.example.org`. Значение содержит адрес до `/api`, без токенов и паролей
4. В **Settings → Pages → Source** выбрать **GitHub Actions**
5. После сохранения файлов в нужной ветке открыть **Actions → Frontend · GitHub Pages → Run workflow**, выбрать нужную ветку
6. Дождаться выполнения `build` и `deploy`. Адрес будет указан у задания `deploy`

Workflow запускается вручную. Он собирает только `frontend/dist`; бэкенд, `.env`, исходные датасеты и PDF хакатона в Pages не попадают. Путь репозитория подставляется из настроек Pages.

Без HTTPS API рабочую серверную версию на Pages запустить нельзя. Если адрес не задан, сайт откроется, но запросы данных покажут сообщение о ненастроенном API. Все переменные `VITE_*` публичные: секретов среди них быть не должно.

## Проверка сборки

```powershell
npm test
npm run build
npm run preview
```

`build` использует адрес из `.env.local` или окружения. Для локальной проверки допускается HTTP localhost, для Pages нужен публичный HTTPS API. Перед `preview` остановить `dev`: обе команды используют `http://127.0.0.1:5173`, уже разрешённый в CORS бэка.

## Файлы

- `src/app.js` — экраны, события, навигация и состояния
- `src/api/http.js` — HTTP, Bearer-сессия, ошибки, PDF
- `src/api/analysis.js` — повторная проверка задания без создания дублей, ID диалога
- `src/api/index.js` — адрес API; локальный режим разработки `npm run demo` существует только для проверки интерфейса без сервера и в сборку не попадает
- `src/demo/` — изолированные синтетические данные
- `src/styles.css`, `src/icons.js` — темы, адаптивная вёрстка, иконки
- `tests/` — проверка HTTP-клиента и восстановления AI-задания

Публикация настроена по [документации Vite](https://vite.dev/guide/static-deploy.html#github-pages) и [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).
