# Проверка фронтенда по требованиям

Проверено по «Альфа Хак — Новостная аналитика», стр. 6–14, внутреннему ALFA_NEWS_TECHNICAL_SPEC.md (§2, §8.5, §12, §17.4), Defense_Guide_Alpha_Hack_2026.docx (критерии и разъяснения). API сверено с текущими `backend/app/api` и Pydantic-схемами, а не со старыми маршрутами внутреннего ТЗ.

## Реализовано в интерфейсе

- Заметная точка входа с главной и постоянный пункт меню
- Первый вход: город и компания; роль задаётся в явно отделённом блоке демонстрации, затем меняется через внешнюю панель прототипа
- В профиле приложения роль только отображается; локальный профиль сохраняется, доступен выход
- Поиск и смена компании по ID, отрасли, городу; личные интересы сохраняются
- Профиль: ОКВЭД, масштаб, регистрация, группа, признаки продуктов; неизвестные данные обозначены явно
- Корпоративные темы с происхождением `rule/manual`, персональное отключение, личные темы
- Формула подбора и объяснение совпадения тем отдельно от AI-разбора
- Первая страница 20 новостей, следующая без повторов; фиксированный порядок снимка
- Дата в МСК, заголовок, текст, темы, источник; отсутствие внешнего URL обозначено
- Обратная связь «Больше / меньше таких тем», отмена повторным нажатием, применение после обновления
- Замечание о неверных и недостающих тегах отдельной формой, без неподдерживаемого комментария
- Задание AI: queued / running / ready / failed; повторная попытка и кеш результата
- Разбор: facts, why_important, risks, opportunities, recommendations, bank_position, limitations
- Разделены факты, AI и материал банка; нет фиктивного мнения банка при отсутствии материала
- Ссылки у утверждений, признаки компании, цитируемый фрагмент, дата и страница отчёта
- Открытие PDF через авторизованный API на цитируемой странице; приватные PDF хакатона в фронтенд не копируются
- Уточнение с conversation_id и источником ответа, ошибка не стирает введённый вопрос
- Панель трассы: контекст, план, поиск, проверка, результат; технические поля скрыты в раскрытии
- Биржа: размер по обороту, цвет по изменению, ноль и неизвестное изменение различаются
- Лидеры отсортированы по абсолютному изменению; время, неизвестная задержка, stale/empty
- Фильтр связи эмитента с компанией обозначен как будущий и отключён, как в ТЗ
- Светлая и тёмная темы, мобильная навигация, анимации, клавиатура и reduced motion
- Сценарии демо: ошибка сервиса, пустая выдача, истёкшие снимок/сессия, лимит AI, таймаут, старый отчёт, stale

## Соответствие текущему API

`src/api/http.js` обращается к FastAPI с Bearer-токеном текущей вкладки. Ключ модели остаётся на сервере. Синтетический адаптер доступен только в локальном режиме разработки и исключается из сборки для Pages.

- Вход/профиль: `/api/companies`, `/api/auth/demo`, `/api/auth/logout`, `/api/profile`, `/api/profile/company`, `/api/profile/settings`, `/api/profile/interests`
- Лента: `POST /api/feed`, `GET /api/feed/{snapshot_id}`; ID новости берётся из `ranking.news_id`
- Чтение: `/api/news/{id}` возвращает StoredNews с `features`, а не произвольные поля карточки
- Реакции и разметка передают `snapshot_id`; показы отправляют отдельный уникальный `event_id`
- AI: создание задания, чтение статуса, чтение AnalysisData.result, trace и questions
- Источник PDF: `/api/report-chunks/{id}` и `/document`; файл открывается через Blob URL
- Биржа: `/api/market`; StockQuote и MarketTile не смешиваются

Роль влияет на ранжирование. Разбор кешируется по компании и новости, поэтому макет не обещает новый текст при смене роли. Темы с нулевым весом не исключают новости полностью. Реакции не меняют порядок уже созданной ленты.

## Проверки подключения

- Вход, каталог компаний, лента, чтение новости, реакция после перезагрузки, интересы, роль и замечание о разметке проверены через настоящий FastAPI и PostgreSQL
- Для проверки использована отдельная компания `demo-api-company` и три синтетические новости из штатного скрипта бэка
- Через интерфейс получены настоящий AI-разбор и уточняющий ответ разрешённой модели `z-ai/glm-5.3-flash`
- Получен `partial`: модель указала ограничения синтетической новости и отсутствие подтверждённой позиции банка
- Повторное открытие восстановило тот же результат и историю, без новых платных запросов
- Дополнительно загружена реальная новость из RSS Банка России от 23.10.2026, размечена моделью и разобрана через интерфейс
- Разбор нашёл связанный отчёт банка, показал цитату и страницу PDF, отдельно обозначил более раннюю дату отчёта
- Общий расход по шлюзу на 25.10.2026 после проверок около 1,34 ₽; проверочный обработчик завершён
- Импортировано девять ранее подготовленных отчётов, без повторного OCR
- Биржевой сервис сохранил 500 котировок; поиск, карточка инструмента, время источника и stale проверены в браузере
- Исходный PDF проверен авторизованным HTTP-запросом: 200, application/pdf, корректная сигнатура файла
- Автотесты проверяют Bearer-сессию, 401, 204, ошибки JSON/HTML, таймаут, PDF, повтор задания и изменение версии данных

## Границы

Итоги повторной проверки контрактов, исправления и оставшиеся задачи: [проверка интеграции](../backend/docs/integration-review.md).

Одна сборка `npm run build` для GitHub Pages. Публичный HTTPS-адрес бэка пока отсутствует, поэтому публикация и работа через интернет не проверены. Настройка описана в [README](README.md).

Банковская авторизация остаётся демонстрационной по контракту существующего API. Полное соответствие критериям хакатона, качество рекомендаций и выводов модели не доказываются проверкой интерфейса. Ограничения сервера не подменяются локальными данными.
